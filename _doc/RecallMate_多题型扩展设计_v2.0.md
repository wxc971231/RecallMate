# RecallMate 多题型扩展设计 v2.0

> 状态：Windows 0.2.9、Android 0.2.1 均已实现并验证。更新日期：2026-11-04。
>
> 设计基线：`main / 7071258`，Windows 0.1.6、Android 0.1.2；下文保留原分阶段设计。
>
> 目标：保留成熟的填空练习，增加判断、单选、多选及答后知识点；外部制题、固定格式导入，软件保持通用、本地、离线、轻量。

## 1. 范围与约束

本文件落实已讨论的精简方案，作为实现与后续平台适配依据；外部详细提案中的审核管理、知识点维护和其他扩展，不自动成为首版任务。

| 首版必须完成 | 本轮后置 |
| --- | --- |
| 填空、判断、单选、多选混合练习 | 综合主观题、联网检索、OCR |
| 混合 JSON 导入、简单追加、内容导出 | 三态审核工作流、审核筛选、答题中撤题 |
| 提交后显示结果、可选解析与关联知识点 | 独立知识库导航、共享知识点编辑与影响管理 |
| 每个题库自己的错题本，支持题型筛选 | 新错题数据库、跨库题目合并、语义去重 |
| 自动保存、进度恢复、旧数据迁移 | 选项乱序、模拟考试、计时和卷面计分 |
| Windows 先验收，再验证 Android | 云同步、账号、复杂复习调度、富文本编辑器 |

继续使用当前 React、TypeScript、Electron、Capacitor 和 JSON 文件存储，不新增服务器、数据库、全局状态库或通用题型插件框架。格式和业务由一套运行时校验负责，不同时维护两套运行时 Schema 校验，也不自制 JSON 解析器。

**内置 LLM 不在产品规划内，不是后置待做功能。** 用户先在软件外独立使用 ChatGPT 合成题目、核对答案，再整理成固定格式导入。应用不集成模型 SDK、API key 配置、模型账号绑定、模型接口预留或后台出题任务；也不自动上传知识点、题库或作答数据。应用职责为本地文件校验、题库管理、练习、确定性判题和学习记录。

导入契约与题目来源解耦：人工编写、ChatGPT 或其他工具产出的文件使用相同格式，不要求 ChatGPT 专属字段。软件只依赖题干、选项、标准答案及可选知识点，不依赖生成模型或生成过程。

情景题是带背景的单选或多选，用 `tags: ["情景题"]` 标记，背景与提问一起存入题干，不新增第五种答题类型。

## 2. 真实材料与验收规模

已核对用户提供的完整知识点和内测卷结构：

| 材料 | 实际结构 |
| --- | --- |
| 知识点 | 105 条，编号 1—105；53 条有填空标记，52 条无标记；部分含多段正文和列表 |
| 填空 | 20 题、80 空，原号 1—13、15—21；不补造缺失的第 14 题 |
| 判断 | 10 题 |
| 单选 | 12 题，含 2 道情景单选 |
| 多选 | 8 题，含 3 道情景多选 |
| 总计 | 50 题；原卷有 3、4、5、6 项选项，也有全部选项应选的多选题 |

知识点按编号块整理，不能按每一行切成一条；普通知识点不强行挖空。显示依据时去掉 `{{...}}` 包装、保留正文；含 `|` 时用第一项作为展示文字。该整理发生在制题阶段，不改变现有填空判题规则。

原题、标准答案、填空边界、否定词及限定条件以用户确认材料为准，不由软件自动改写。单选第 9 题当前为正向提问，转换时保留修订稿。转录注和缺失占位不作为试题。

内测卷转录本身没有标准答案。外部提案中的答案表与知识点映射作为待核参考；完整 50 题转换验收前，需要使用用户确认的答案表。缺少的答案列为待补，不把模型推断或提案自报的“已确认”当成核对结果。此前阶段可先使用中性示例推进开发。

真实内测卷、完整知识点、答案照片及其转换结果只放用户目录或被 Git 忽略的本地夹具目录，不复制到公开示例、CI 或发布包。附带的[中性示例](examples/mixed-demo.questionbank.json)另行编写，供公共开发使用。

## 3. 题库、错题本与练习入口

每个题库保留自己的全部题目、统计和错题标记，继续使用题库内 `stats[questionId]`。错题本是原题的筛选视图，不复制题目，不另建错题集合。

- **本库错题**：只显示当前题库的错题，混合包含四种题型。
- **全局错题**：保留现有汇总入口，按题库分组；从某组开始复习时只练该库。
- **本轮错题**：保持现有临时重练入口，和长期错题本区分。
- **题型筛选**：全部／填空／判断／单选／多选，作用于当前列表；按筛选结果开始练习时固定该轮题目队列。

移出错题本保留原题和历史统计；删除原题或题库时一并清理相应错题引用。保留错次、求助次数和最近困难时间的排序规则。首版不增加正确率仪表盘和知识点掌握度统计。

## 4. 混合内容文件

### 4.1 区分内容导入与学习恢复

| 文件 | 识别方式 | 内容 |
| --- | --- | --- |
| `.md` / `.txt` | 现有填空解析器 | 原 `{{答案}}`、`|`、独占行 `---` 语法保持 |
| `.questionbank.json` | `format: "recallmate.question-bank"`、`version: 1` | 题目和可选知识点，不携带学习记录 |
| `.recallmate.json` | V2 备份标记；兼容旧 V1 备份 | 题库、统计和会话，走恢复确认 |

按内容标记分派 JSON，不按文件名猜版本。JSON 解析或版本错误直接提示，不退回填空文本解析；以 `{{` 开头的旧题不能误判为 JSON。文件选择和粘贴均支持混合包，不新增一套混合 Markdown 语法。

### 4.2 最小契约

```json
{
  "format": "recallmate.question-bank",
  "version": 1,
  "bank": { "id": "stable-bank-id", "name": "题库名称" },
  "knowledgePoints": [],
  "questions": []
}
```

以上只展示外壳，正式文件至少有 1 题。完整可用文件见[中性示例](examples/mixed-demo.questionbank.json)。内容格式版本、内部存储版本和应用发布版本互相独立。

| 对象 | 必需字段 | 可选字段 |
| --- | --- | --- |
| bank | 稳定外部 `id`、`name` | `description` |
| knowledgePoint | 包内唯一 `id`、完整 `content` | `title`、`source`、`locator` |
| question | 稳定外部 `id`、`type`、`stem`，以及该题型的答案 | `label`、`knowledgeRefs`、`explanation`、`tags`、`source` |

`knowledgePoints` 可省略或为空。解析、知识点与来源定位不强制填报；提供引用时，必须在同一包内有对应正文，不能引用一个需要另行联网获取的条号。用户在外部制题时可以要求提供完整解析与依据，但不把这些质量要求全部变成通用导入的硬门槛。

外部 ID 使用 1—80 位字母、数字、点、下划线或连字符，首位为字母或数字。内部磁盘题库文件名仍使用 UUID，不能把外部 ID 当作文件路径。来源只作文本元数据，不触发网络请求。

题目的 `source` 为可选对象，`kind` 使用 `manual` / `exam` / `ai`，可附 `name`、`locator`、`batchId`；知识点的 `source` 则是可选来源名称字符串。`label`、`tags` 仅用于定位和筛选，不参与答案判断。

| type | 答案格式 | 规则 |
| --- | --- | --- |
| `cloze` | 答案内嵌于 `stem` 的 `{{...}}` | 按原解析器恰好解析为一道题，不另存 `answer` 或 `options` |
| `true_false` | `answer: true` 或 `false` | 真布尔值，拒绝字符串、0、1；无 options |
| `single_choice` | `answer: "B"` | options 为 `{id,text}` 数组，答案是一个有效选项 ID |
| `multiple_choice` | `answer: ["A","C"]` | 不重复的有效 ID 集合，至少 2 项，可为全部选项 |

选项支持 2—26 项，按文件顺序展示，不硬编码 4 项。显示字母与选项 ID 分离，按 ID 判题；选项文字不重复写字母前缀。非填空题不能同时包含填空交互标记。

不要求 `reviewStatus`、`reviewNote`，不建设长期审核状态机。兼容旧提案中的这些字段时在预览展示提醒；含 `draft` / `needs_review` 的包，必须明确确认整批进入练习，不能因校验成功就默认为已经审题。其他未知字段提示后由用户确认忽略，不能掩盖缺失或拼错的必需答案字段。

### 4.3 校验与错误提示

沿用 UTF-8、20 MiB 单文件上限、每库最多 10000 题；允许 UTF-8 BOM，读取时去除。写入和读取按 UTF-8 字节采用同一尺寸限制。题库名 1—120 字符，题干、知识正文和解析各不超过现有 100000 字符级上限。

必须检查：顶层标记和版本、题型与答案类型、重复题 ID / 知识点 ID / 选项 ID / 多选答案 ID、非空文本、重复选项文字、答案是否存在、知识点引用是否完整。判断答案 `false` 合法，不能用真假值判断是否缺少答案。

错误定位到题号及字段，例如 `questions[3].answer：选项 D 不存在`；尽量一次报告多个问题。有错误时整批不落盘，不静默导入一部分。普通结构校验不证明题目语义正确，也不自动反转“错误的是”一类题目的答案。

## 5. 导入、追加、编辑与导出

导入预览只展示必要信息：题库名、各题型数量、填空总空数、知识点数、前几道题、重复和冲突提示。确认后选择新建题库或追加到现有题库。发现同一来源已经导入过时提示选择目标，不静默再复制一份。

简单追加遵守以下规则，不做内容同步系统：

1. 用户选择目标库，不要求先导出旧库取得来源 ID，也不限制只能向相同来源的库追加。
2. 题目的外部 ID 在目标库内唯一；同 ID 同内容跳过，不动原统计。同 ID 不同内容整批报冲突，不提供自动覆盖合并。
3. 知识点同 ID 同内容复用，同 ID 不同内容报冲突。不同来源的 ID 撞车时明确提示调整外部 ID、同步引用，或另建题库，不猜测合并关系。
4. 按字段内容比较，忽略 JSON 缩进及对象键顺序；多选答案按集合比较，选项顺序仍有意义。不做语义去重。
5. 只追加新题时保留原会话和统计，新题下一轮进入队列；全是重复项时不重新保存。数量或尺寸越界整批拒绝。
6. 先构造临时结果，再经既有保存队列一次写入；失败时保留原库及导入预览，成功后才提示已导入。

保留简单题目新增与编辑：选择题型、填写题干、选项、答案、可选解析和引用。已有题暂不直接切换类型。知识点先从内容包导入与展示，不同时增加独立知识点维护界面。

修改题干、选项或答案前提示重置该题统计并清除该库当前会话，其他题统计保留；只改 label、tags、解析和来源说明可保留统计与会话，不借编辑展示字段清空用户草稿。删除行为继续遵守原有引用清理规则。

题库菜单区分 **导出题库内容** 与 **导出学习备份**。前者不含个人统计与会话，后者完整保留；通过现有受限平台桥接扩展导出能力，不把内容包强制转换成 Bundle。

## 6. 作答与答后阅读

### 6.1 客观题统一过程

```text
未选择 → 选择或修改 → 显式提交 → 锁定选择并显示反馈 → 下一题
```

判断题默认两项都未选，单选默认无选项，多选默认空集合。空选择提交只提示、不结算；多选只选 1 项也可以提交，应照标准集合判错，不能要求用户先凑够 2 项。

客观题提交后不在同一次作答中反复改选；再练产生新 Attempt。错误选择也进入已提交状态，不会被当成“尚未完成、可以一直改到正确”。

- 单选按选项 ID 相等判定；判断按布尔值相等判定。
- 多选按精确集合相等判定，点击顺序无关；少选、多选、错选均为整题错误，无部分得分。
- 多选反馈分别显示已选应选项、错选项、漏选项，用绿／红／黄色及文字区分。
- 对“错误的是”题干，使用“本题应选”措辞，避免把应选的错误表述称为正确知识。
- 判断反馈区分“本题答对／答错”和“你的选择：正确／错误”，不能只显示一个含糊的“错误”。

客观题工具栏保留“提交答案、不会／看答案、跳过、下一题”。提交前主动看答案记求助；直接跳过不公开答案、不新增错题。提交后阅读答案、解析与知识点不记求助。

### 6.2 填空与严格模式保留

保留现有文本语法、可接受答案、逐空判题、字符反馈、提示、按住答案、IME 和快捷键行为。Windows 的严格模式默认开启；一个空内和跨空并列内容均按原文顺序，关闭后保留既有换序能力。

**严格规则绑定本题 Attempt**：设置变更从下一题或新练习起生效，恢复草稿时使用原 `strictBlankOrder`，不能取当前设置重新判断。旧作答缺少该字段时继续表示原宽松规则，不能补成 true。全局设置缺少该字段时默认 true；这两个默认值不同。

### 6.3 反馈、知识点与双端交互

共用当前练习页面外壳、顶部进度与底部按钮。在题目下方设置一处答后反馈区：结果 → 用户选择／本题应选 → 可选解析 → 相关知识点。首条依据可展开，其余折叠；未关联时不显示空卡片，不增加新的侧栏或知识库页面。

作答前不把解析和知识点正文渲染到页面或可访问树。旧填空只在整题完成或放弃后显示知识点，避免答完第一空就泄露后面的答案。长题干、长选项及知识正文能滚动，下一题按钮可达，全部按纯文本渲染。

桌面 submit、giveUp、skip 按现有自定义配置复用；F1 对应的按住答案与 F2 对应的提示在客观题停用。键盘处理必须允许焦点在原生 radio / checkbox 上提交，不能沿用“所有非填空 input 都屏蔽”的判断；Tab、方向键、Space 维持控件原生语义。

忽略重复 keydown，弹窗、编辑器与输入法组合时暂停答题快捷键。提交和下一题是两个动作；动作携带当前 attemptId，过期事件不作用到下一题。保留现有界面防连点，但不靠防抖代替领域层防重复结算。

Android 客观题不主动唤起软键盘，从填空切入时清理上题焦点和键盘状态。保留现有填空键盘收起导航、独立滚动、提示和按住答案保持键盘的行为。

## 7. 数据与状态的最小改造

Question 按 `type` 使用 TypeScript 判别联合，四类共用 ID、`sourceText` 和时间字段；外部 `stem` 导入时映射为现有 `sourceText`，不重命名整套旧代码。各题型只携带自己的答案与选项，不使用 `answer: any` 或一组相互矛盾的可选字段。

内部 ID 继续用 UUID。题库新增稳定 `contentId` 供内容导出使用，题目保留包内 `externalId` 供追加查重；知识点 ID 在本库内唯一、只用于引用，不参与磁盘路径。旧库缺少导出身份时使用 `legacy-<UUID>`，不要求用户重建题库。

Attempt 公共部分继续保留统计快照、时间和求助标记，按题型分支：

| 分支 | 保存内容与状态 |
| --- | --- |
| 填空 | 现有 blanks、activeBlankIndex、charSources、strictBlankOrder 原样保留；active / completed / abandoned / skipped |
| 判断 | 一份 `selectedAnswer: boolean 或 null`；active / submitted / abandoned / skipped |
| 单选 | 一份 `selectedAnswer: 选项ID 或 null`；同上 |
| 多选 | 一份 `selectedAnswer: 选项ID数组`，初始空；同上 |

客观题增加明确的 `submitted` 状态，避免把“completed 一定答对”的旧假设套到错误提交上。提交后锁定同一份 selectedAnswer，不额外保存一份 submittedAnswer；结果由题目与已选答案计算，不再持久化一份重复 result。恢复时按同一判题函数校验状态与错误标记，不能直接相信文件自报的正确结果。

复用 `beforeStats` 投影，保持现有进入一次 Attempt 即增加一次 attemptCount 的口径。错题、求助、独立完成、移出错题标记均延续；重复提交不自动 next，也不重复累加。总结仍在 next 时追加，summary 数量等于 currentIndex；保留现有六项总结，不臆造旧历史缺少的判分信息。

## 8. 旧数据迁移与回退

内部学习备份升为 `format: "recallmate.backup"`、`schemaVersion: 2`，Bank 和 Session 对应升级。只在输入边界读取 V1 并转换为统一 V2，不长期维护两套运行时判题或 UI。

迁移必须保留：题库／题目／会话／作答 UUID，原文、时间、所有输入与字符来源、partial 状态、焦点、队列及总结、beforeStats、错题统计、求助标记、wrongBookDismissed 和 **strictBlankOrder**。旧题补 `type: cloze`，知识点与引用为空；设置文件的版本、字号、快捷键及严格模式偏好不重置。

迁移不能调用 createBank、startSession、createAttempt、projectStats 重新生成数据，也不能重新判题和累计统计。只读加载先在内存转换；首次写 V2 前为原始 V1 字节保存一次不可轮换的迁移副本，例如 `data/migrations/<bankId>.v1.original.json`。普通轮换 .bak 不能代替该副本。

备份失败则不覆盖旧文件，允许重试；重复加载／保存不重复迁移。未知更高版本应提示使用匹配的新应用，不把它当损坏后自动回退旧备份再覆盖。V2 不承诺旧应用能读取，不导出丢弃客观题的伪 V1 备份。

Windows、Android 与浏览器预览共用迁移规则，各存储适配层保存原件。Windows 先发布时说明混合备份需要支持 V2 的 Android 新版；Android 0.1.2 不能被宣称支持新混合备份。回退旧程序使用迁移原件，不能假称它包含升级后的新增学习记录。

## 11. 外部制题与软件职责

采用以下工作流，不建设应用内命题能力：

```text
知识点文档／原始试题
  → 用户在软件外单独使用 ChatGPT 合成题目
  → 外部核对题干、选项、标准答案及知识点依据
  → 整理为固定的 .questionbank.json 内容包
  → RecallMate 本地校验、预览、新建／追加题库
  → 离线练习、确定性判题、错题和进度保存
```

先用已有内测卷验证软件，再逐批增加外部生成的题目。制题时保留知识点编号及完整条件、范围、例外，不强行要求每条知识点生成全部题型；入库前检查单选唯一、多选集合完整、判断无歧义及依据是否支持答案。题目的语义审核在应用外完成，软件格式校验不代表命题正确。

大量题目可分批整理，每批使用完整内容包、稳定的题库 ID 和不重复的题目 ID，并附实际引用的知识点正文。后续通过第 5 节的简单追加规则汇入题库；不要把聊天回复、提示词、代码围栏或只有 questions 数组的片段直接当正式导入文件。

应用只读取最终整理好的内容，不解析聊天记录、不执行提示词、不联系 ChatGPT，不在导入、提交或显示解析时调用模型。`source.kind: ai` 等可选来源字段仅作说明，与判题、生成和联网权限无关。确认入库后，即使不再使用 ChatGPT，题库仍能正常离线练习。
